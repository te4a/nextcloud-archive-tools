# Archive Tools

[English](../README.md) · [Подготовка стабильного релиза](RELEASE.md)

Кандидат `0.5.0-beta.2` готовится к выпуску. Матрица Nextcloud 34/35 с PostgreSQL, SQLite, MariaDB и MySQL пройдена для предыдущего кандидата `0.5.0-beta.1`. Версии и результаты его проверок приведены в [отчёте](VALIDATION.md).

У кандидата есть настраиваемые сервером лимиты подключений, активных заданий и сохранённых метаданных. При достижении лимита новое действие отклоняется; администратор может явно очистить историю завершённых заданий без удаления пользовательских файлов. Порядок настройки и восстановления описан в [инструкции установки](INSTALL.md#resource-limits-and-task-history).

Нативное приложение для **Nextcloud 34–35 и PHP 8.5**. Целевая установка — официальный образ `nextcloud:34.0.5-apache`, PHP 8.5.12. Приложение написано с нуля: PHP на сервере, Vue/TypeScript в интерфейсе, штатные файлы, права доступа, уведомления и фоновые задания Nextcloud. Для установки в существующий Nextcloud отдельные контейнеры не нужны. Версия выпуска указана в `app/appinfo/info.xml`; имя установочного пакета формируется из неё автоматически.

Приложение работает с **ZIP, TAR, TAR.GZ/TGZ, TAR.BZ2/TBZ/TBZ2, TAR.XZ/TXZ, 7z и RAR**. Нужны 64-битный PHP и расширение `intl`. Для ZIP используется расширение `zip`, для TAR.GZ — `zlib`. Несжатый TAR читается средствами PHP.

Для 7z, RAR, TAR.BZ2 и TAR.XZ пакет `0.5.0-beta.2` включает официальный `7zz` версии 26.06 для Linux x86-64 и ARM64. Приложение сначала проверяет комплектный бинарник для своей архитектуры. Если его нельзя запустить, проверяются системные `7zz` и `7z`. Полная сборка поддерживает распаковку RAR. В меню доступны форматы, которые поддерживает выбранный бинарник. [Сайт 7-Zip](https://www.7-zip.org/)

Для запуска декодера нужны исполняемый `/usr/bin/prlimit` из `util-linux`, разрешённые функции PHP `proc_open`, `proc_get_status`, `proc_terminate`, `proc_close` и хотя бы одна из функций `link` или `symlink`. Файловая система должна разрешать выполнение выбранного бинарника. Каждый дочерний процесс ограничен 512 МиБ адресного пространства и 300 секундами CPU, а время ожидания ограничено 300 секундами. Декодирование использует не более двух потоков. Сжатый TAR проверяется до полного окончания потока. Конкатенированные gzip-потоки и разреженные TAR-файлы не поддерживаются.

Декодер читает выбранный файл через ссылку в отдельном приватном временном каталоге. Это исключает подхват соседних томов. При закрытии потока ссылка удаляется. Ссылки старше часа, оставшиеся после аварий, убирает штатная фоновая очистка. Исходные архивы сохраняются.

## Что работает

- Русский и английский интерфейс, включая серверные ошибки и уведомления; язык выбирается настройкой Nextcloud пользователя.
- Архив открывается внутри приложения «Файлы» как временная папка: штатный список, сортировка, выбор элементов и хлебные крошки. Кнопка «К файлам» возвращает в исходную папку с фокусом на исходный файл; работают переходы браузера и прямые ссылки на вложенные каталоги. Администратор может назначить открытие по клику для всех пользователей.
- Скачивание отдельного файла, полная или выборочная распаковка и подключение доступны прямо в этом списке. Выбор действует в текущем каталоге, как в обычной навигации Files. Очередь операций и управление подключениями остаются на отдельной странице Archive Tools.
- Подключение архива как папки только для чтения рядом с исходным файлом. В обычной папке, которой поделились с пользователями или группой, подключение видно всем, кто имеет доступ к исходному архиву и этой папке. Изменения прав и отзыв доступа учитываются; уход создателя подключения не отключает архив для остальных участников.
- Защищённые архивы: пароль для просмотра, скачивания, подключения и распаковки. Для подключения и ожидающего задания пароль хранится в зашифрованном виде средствами Nextcloud; завершённое задание удаляет сохранённый пароль. Системному архиватору пароль передаётся через stdin.
- Распаковка через очередь Nextcloud: прогресс, отмена, повторный запуск и штатное уведомление о результате. Права на источник и папку назначения проверяются повторно при выполнении задания.
- Общий для всех участников таймер простоя, закрепление подключения, защита активного чтения и распаковки от автоматического отключения.

## Права и поведение файлов

Подключённый архив не предоставляет дополнительных прав: чтение требует текущего доступа к источнику. Создание подключения требует права создавать содержимое в родительской папке. Закрепление и общее отключение доступны пользователям с правом управления подключением. Удаление получателем корня общей папки означает отказ от общего доступа, как в Nextcloud, и не удаляет общее подключение у остальных.

Подключение не распаковывает архив в папку пользователя. Отключение удаляет только виртуальную папку, сохраняя исходный архив и ранее извлечённые файлы. Если исходный файл удалён, его подключение убирается фоновой очисткой. Если содержимое архива изменилось, старое подключение становится недоступным: его нужно отключить и подключить заново.

Обычное открытие архива не создаёт подключение. Временный список виден внутри Files; после действия «Подключить как папку» папка становится доступна и по обычному WebDAV-пути Nextcloud. Участники читают её под своими учётными записями. Запись, создание каталогов, удаление и перемещение содержимого подключённого архива запрещены.

Временные элементы имеют собственные адреса и идентификаторы только для интерфейса. Они не выдаются за реальные WebDAV-файлы: действия редактирования, удаления, общего доступа и другие обычные операции Files в этом представлении отключены. Пароль хранится в памяти открытого просмотра и очищается при выходе; после перезагрузки защищённого архива его нужно ввести заново.

Скачивание, распаковка и подключение сравнивают `expectedEtag` с текущим ETag источника Nextcloud. Если тег изменился после открытия, операция возвращает HTTP 409 с предложением открыть архив заново. Параметр необязателен для совместимости прежних API-клиентов. Проверка опирается на версию метаданных Nextcloud: на локальном хранилище перезапись с прежней временной меткой, в том числе в пределах одной секунды, может сохранить прежний ETag.

Распаковка создаёт новую папку с выбранным именем и не перезаписывает существующую. При обычной ошибке или отмене приложение удаляет созданную им неполную папку. При аварийном завершении PHP уже записанная часть может сохраниться: восстановление фоновой очереди отмечает задание как неуспешное и сообщает о частичном результате. Не удаляйте эту папку до проверки, если в неё могли добавить свои файлы.

Проверка архива отклоняет выход за границы пути, ссылки, специальные файлы, неоднозначные имена и коллизии после нормализации Unicode. Текущие пределы: 10 000 записей, 4 ГиБ суммарного распакованного размера, глубина 32, 8 МиБ на имена записей. Каждый компонент имени после нормализации ограничен 250 байтами UTF-8: такой предел применяет штатная проверка имён Nextcloud. Распаковка потоковая, но при источнике из удалённого хранилища может потребоваться временная локальная копия архива. TAR, включая сжатые варианты, распаковывается за один последовательный проход. Для solid-архивов 7z/RAR чтение отдельного файла может потребовать декодирования предшествующих данных.

## Общие настройки

В настройках администрирования Nextcloud откройте раздел Archive Tools.

| Настройка | По умолчанию | Поведение |
| --- | --- | --- |
| Открывать архивы по клику | Включено | Общее правило для поддерживаемых форматов в приложении «Файлы»; действия меню остаются доступны |
| Простой до отключения | 60 минут | От 0 до 10 080 минут; 0 отключает очистку по простою |
| Разрешить закрепление | Включено | Закреплённое подключение не отключается по простою |
| Хранить историю операций | 30 дней | 0 — бессрочно; удаляются только старые записи завершённых операций, до 200 за проход. Ошибки и отмены с частичным результатом сохраняются для проверки; извлечённые файлы не удаляются |

Активность общая: открытие содержимого подключённой папки или чтение файла любым участником продлевает срок. Простое перечисление родительской папки и фоновые превью не удерживают архив подключённым бесконечно. Во время активного потока или распаковки действует временная защита; после аварии процесса она истекает автоматически.

Очистка запускается обычным cron Nextcloud с интервалом около пяти минут, включая часы вне окна обслуживания. При исправном cron отключение происходит на ближайшей проверке после истечения срока, обычно с погрешностью до пяти минут; очередь и длительные задания могут увеличить задержку. Восстановление прерванного задания начинается после 15 минут без его активности и очередного запуска очистки.

## Установка в существующий Nextcloud

Готовый архив содержит собранный интерфейс. Node.js и pnpm нужны только для разработки.

1. Сделайте обычную резервную копию Nextcloud и сначала проверьте приложение на тестовом экземпляре.
2. Распакуйте `dist/archive_tools-<версия>.tar.gz` в каталог дополнительных приложений, например `/var/www/nextcloud/custom_apps`. Получится `custom_apps/archive_tools/appinfo/info.xml`.
3. От имени пользователя веб-сервера выполните команды, скорректировав путь и пользователя под свою установку:

```sh
sudo -u www-data php /var/www/nextcloud/occ app:enable archive_tools
sudo -u www-data php /var/www/nextcloud/occ upgrade --no-interaction
sudo -u www-data php /var/www/nextcloud/occ background:cron
```

В существующей установке должен регулярно выполняться `cron.php` Nextcloud от имени пользователя веб-сервера, обычно каждые пять минут. Очередь распаковки, автоматическое отключение и восстановление после аварий зависят от этого cron. Если он уже настроен, используйте его; отдельный worker приложения не нужен.

Для отключения приложения используйте `occ app:disable archive_tools`: исходные архивы и извлечённые файлы сохраняются, виртуальные подключения исчезнут. Повторное включение сохраняет настройки и записи подключений в базе. Перед заменой версии сохраните также предыдущий каталог приложения; откат базы выполняется из резервной копии Nextcloud вместе с файлами.

Для диагностики от имени пользователя веб-сервера выполните `php occ archive_tools:diagnose --output=json` из каталога Nextcloud. Отчёт показывает версию PHP, тип БД, доступные форматы, настройки приложения и давность последнего cron. Пароли, пути к данным, пользователи и имена файлов в отчёт не включаются. До установки приложения тип БД можно узнать штатной командой `php occ config:system:get dbtype`.

Перед пилотом на рабочем сервере проверьте его БД и хранилище, установите необходимые системные пакеты в окружение, где работает PHP, и настройте cron. На локальном диске уже проверены обычные общие папки, права, распаковка, конкурентные операции и восстановление после остановки PHP. Реальная нагрузка рабочего сервера, другие БД, автоматизация браузерного прогона и длительный пользовательский пилот остаются отдельными этапами проверки.

### Если Nextcloud работает в Docker

Комплектный `7zz` запускается из каталога приложения внутри существующего контейнера Nextcloud/PHP. В этом окружении должен быть доступен `/usr/bin/prlimit`. Если `app` и `cron` работают в разных контейнерах, используйте одни и те же файлы приложения и одинаковое окружение PHP с одной архитектурой.

Если нужен системный декодер для резервного запуска, пример `dev/Dockerfile` из репозитория добавляет полный 7-Zip в образ `nextcloud:34.0.5-apache` для x86-64. Скопируйте его как `Dockerfile.nextcloud` в каталог существующего Compose-проекта и используйте образ с той же версией Nextcloud, что и в вашей установке. Для обоих сервисов укажите один производный образ. [Пример Dockerfile](../dev/Dockerfile)

```yaml
services:
  app:
    image: nextcloud-with-archive-tools:34.0.5
    build:
      context: .
      dockerfile: Dockerfile.nextcloud
  cron:
    image: nextcloud-with-archive-tools:34.0.5
```

Сохраните существующие тома, переменные окружения, порты, entrypoint сервиса cron и настройки PostgreSQL/Redis. Соберите образ через `docker compose build app`, затем пересоздайте `app` и `cron` штатным способом. Приложение устанавливается в общий `custom_apps` по инструкции выше и использует обычный cron Nextcloud.

Тип БД в официальном контейнере можно узнать командой `docker exec --user www-data ИМЯ_КОНТЕЙНЕРА php /var/www/html/occ config:system:get dbtype`. После установки приложения используйте аналогично `archive_tools:diagnose --output=json`. Эти команды не выводят пароль БД. Если после включения через CLI веб-интерфейс временно возвращает 404, перезапустите PHP-контейнер штатным способом для вашей установки, чтобы обновить веб-кеш маршрутов.

## Локальная проверка на Windows

Нужны Docker Desktop, PowerShell, Python 3, Node.js 24 LTS либо 26+ и pnpm указанной в `package.json` версии. Локальный runner ищет pnpm CLI рядом с Node.js; одного Corepack shim в PATH недостаточно. Перед первым полным прогоном установите зависимости интерфейса командой `pnpm install --frozen-lockfile --store-dir .pnpm-store` в корне репозитория. Скрипт сам ничего не устанавливает через npm и не меняет системные настройки.

```powershell
.\dev\test.ps1 -Start
```

`-Start` поднимает только проект `archive-tools-dev` из `compose.yaml`, создаёт случайный пароль администратора в локальном `.env`, если файла ещё нет, и сохраняет том Nextcloud. Вход: `http://127.0.0.1:18080`, пользователь `admin`, пароль — значение `ARCHIVE_TOOLS_ADMIN_PASSWORD` в `.env`. Не публикуйте этот файл. Каталог приложения подключён к контейнеру только для чтения; магазин приложений отключается только на этом локальном стенде.

Последующий прогон на работающем стенде:

```powershell
.\dev\test.ps1
```

Скрипт проверяет локальный Docker endpoint, метки проекта, порт и путь примонтированного приложения. Затем включает актуальный код приложения, запускает `occ upgrade`, проверяет синтаксис PHP и обязательные наборы ZIP/TAR/7z/RAR, плана извлечения, хранения истории и безопасных DTO. После этого проверяет полноту переводов RU/EN, тесты состояния и маршрутов интерфейса, типы и сборку. Последовательно выполняются HTTP-наборы: общий доступ, жизненный цикл, просмотр и распаковка, запрет записи через WebDAV, проверка версии архива, безопасность очереди, новые форматы и конкурентная работа. Последний набор проверяет фактический SIGKILL собственного фонового задания; срок блокировок и heartbeat затем ускоряется только для его тестовых данных. Все наборы обязательны. Для pnpm используется доступный рядом с Node.js CLI. Результаты и журналы сохраняются отдельно в `.test-results`; успешность требует нового отчёта текущего запуска.

Параметр `-SkipFrontend` явно пропускает проверки и сборку интерфейса, если нужны только серверные проверки. Для подготовки установочного пакета сначала выполните полный прогон. HTTP-тесты создают временных пользователей и данные только в указанном локальном проекте. После успешного выполнения тестовые данные удаляются; при ошибке могут сохраниться для диагностики.

После успешного прогона скрипт включает штатный cron образа через `flock` и проверяет запуск daemon по PID и журналу `/tmp/archive-tools-cron.log` внутри контейнера. Перед повторным прогоном он останавливает только собственный daemon, чтобы cron не вмешивался в детерминированные проверки, и запускает его снова после успеха. При неуспешном прогоне cron остаётся остановленным. После перезапуска контейнера повторите `dev/test.ps1`, чтобы вернуть этот локальный daemon. При необходимости однократного выполнения фоновых заданий на стенде:

```powershell
docker compose --project-name archive-tools-dev --file compose.yaml exec -T --user www-data nextcloud php -f cron.php
```

## Установочный пакет

После полной проверки:

```powershell
.\dev\package.ps1
```

Результат — `dist/archive_tools-<версия>.tar.gz` и файл SHA-256. Версия берётся из `app/appinfo/info.xml`. Пакет содержит один корневой каталог `archive_tools` с серверным кодом, готовыми JS/CSS, локализациями, бинарниками 7-Zip и сведениями о лицензиях. Файл `SOURCE.md` указывает версию исходников Archive Tools. Для пересборки интерфейса и запуска тестов используйте полный репозиторий. [Инструкция для разработчиков](../CONTRIBUTING.md)

7-Zip разработан Игорем Павловым. Основная лицензия — GNU LGPL. В каталоге `bin/` рядом с бинарниками поставляются исходники версии 26.06 и оригинальные тексты лицензий, включая условия BSD и unRAR. [Лицензии 7-Zip](../app/bin/License.txt)

В репозитории код приложения расположен в `app`, тесты — в `tests`, средства локального запуска — в `dev`. Локальный образ для x86-64 собирается из закреплённого Nextcloud 34.0.5 и официального 7-Zip 26.06 с проверкой SHA-256. PostgreSQL и Redis в Compose нужны для проверки серверной конфигурации. Текущий стенд использует `archive-tools-dev_nextcloud34pgsql`; прежние SQLite-тома 34 (`archive-tools-dev_nextcloud34`) и 35 (`archive-tools-dev_nextcloud`) сохранены. Приложение работает в существующем Nextcloud; образ добавляет зависимости внутри его PHP-контейнера.

## Текущие ограничения

- Поддерживается чтение и распаковка. Создание и редактирование архивов не реализованы.
- Одиночные сжатые потоки `.gz`, `.bz2`, `.xz`, не содержащие TAR, не открываются как папки. Самораспаковывающиеся и многотомные архивы не входят в поддерживаемый набор.
- Обычные общие папки пользователей и групп проверены. Team folders («Групповые папки»), публичные ссылки и федеративный доступ не входят в проверенную область MVP.
- Внешние хранилища с персональными учётными данными и другие источники, недоступные штатному фоновому заданию без пользовательской сессии, не поддерживаются для распаковки; совместимость прочих внешних хранилищ отдельно не гарантируется.
- Архив внутри другого подключённого архива нельзя подключить или отправить в очередь извлечения напрямую. Сначала извлеките внутренний архив в обычную папку Nextcloud.
- Большие и изменённые архивы не переиндексируются автоматически. При превышении лимитов операция отклоняется с объяснением.
